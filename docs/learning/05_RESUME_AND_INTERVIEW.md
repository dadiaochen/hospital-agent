- 项目介绍按“为什么做、我负责什么、我怎么解决、结果怎样”组织。这个结构符合 STAR，但面试时不说 STAR，也不念“背景、任务、行动、结果”。

- 只写已经实现和验证的内容。设计目标、固定响应验证、真实模型效果和生产结果必须分开。
- 不删除暂时答不好的问题。涉及个人实习经历、使用过的产品或线上指标时，先补充真实背景，再写成答案。

## 6. 项目难点与口头回答

### 难点一：不是“能不能回答”，而是“能不能在边界内完成任务”

这个项目最大的难点不是让模型生成一段医疗回答，而是防止它越过业务边界。我的处理是把高风险识别、工具权限和人工确认放进工作流，由程序控制节点顺序。涉及停药、调整剂量、换药或严重症状时，在生成待确认内容之前直接拦截；复诊、购药和提醒也只能先生成本地待确认内容。这样即使模型输出不稳定，也不能跳过关键门禁。

### 难点二：一个账号管理多人，必须防止家庭成员数据串用

本人、父亲和母亲的数据会同时存在，如果把完整聊天记录直接交给所有角色，很容易把上一位成员的处方或药箱信息带到下一位成员。我在入口确认当前用户和家庭成员，每次工具查询继续校验所属关系，并给不同角色只提供最小必要上下文。任务结束或切换成员时清理临时上下文，只保留已确认事实、资料来源和运行摘要。

### 难点三：Agent 出错后要能回答“哪一步错了”

只保存最终回答无法判断问题来自意图识别、工具参数、数据库结果、RAG 还是模型输出。我把一次任务和每次工具调用分别记录，保留输入、输出、耗时、失败类型、降级动作和资料来源。前端可以查看运行轨迹，固定用例也能基于同一份记录做 Agent 评测。

### 难点四：RAG 不只是召回，还要保证正文与来源一致

向量召回服务可能不可用，召回结果也不能直接当作医疗事实。我保留关键词检索作为稳定基线，向量检索只负责返回资料位置，再从数据库读取规范正文；失败时记录原因并回退。这样可以区分“找到了哪份资料”和“最终引用了什么内容”，不会让模型自己补规则。

### 难点五：大模型输出不稳定，但后端接口必须稳定

模型可能超时、返回非 JSON、缺字段，或者输出不符合安全要求。我没有让业务代码直接消费模型原文，而是通过统一入口做结构解析、数据校验和安全检查，失败后记录原因并按同一输出结构降级。测试环境默认使用固定响应，先验证工作流和异常路径；这不能替代真实模型评测，但能让后端行为可重复。

- 系统能够诊断、自动开方、修改剂量或代替医生判断。
- 固定用例证明了临床安全、零幻觉或生产环境性能。
- 已使用真实向量数据库并获得明确召回率提升。
- 已上线生产并拥有真实用户、准确率、成本或延迟指标。

## 10. 待本人确认的信息

下面问题不能从代码仓库或当前简历中可靠推断，确认后才能生成最终简历和实习面试答案：

1. 这张 Dify 画布由你独立完成哪些部分，导师或其他同事参与了哪些部分。
2. 实习使用的 Dify 版本、部署方式和模型服务；这些只在技术追问中回答，不放进项目开场。
3. 知识库具体包含哪些资料，由谁审核和更新，是否做过召回效果或错误案例整理。
4. 实习中实际接入了哪些后端接口；统一接口层是你实现、参与实现，还是直接调用已有能力。
5. 智能舌诊服务的真实输入、输出和失败处理；患者智能体是否只负责收集信息和展示已有结果。
6. 已确认：教程原型未接入真实药物相互作用服务。面试中只能说明风险边界并引导患者咨询医生或药师，不能把它描述成已经完成的药物相互作用判断能力。
7. 当前代码项目是实习后的个人延伸，还是与实习完全独立的同类业务项目。
8. 实习项目属于内部演示、测试环境还是正式上线阶段；该信息只用于说明项目状态，本版 Dify 实习经历不写效果指标。
9. 项目周期、团队人数、你的职责边界，以及一个最有代表性的错误案例和改进结果。
10. 你实际使用过哪些 Coding Agent，以及使用深度。此项确认后再写面经答案，不再用“按真实经历回答”代替答案。

## 11. 后续面经生成规则

后续面经必须从这份项目经历和真实实习经历反推，不再先堆一套与简历无关的八股：

1. 项目面经围绕简历中的每个亮点继续追问设计、取舍、异常和验证。
2. 实习面经保留 Dify 工作流、RAG、工具调用、Function Calling、知识库和错误案例等真实做过或高度相关的问题。
3. Agent 测试、AI 代码测试和 Agent 评测同时出现在 Agent 面经与测试开发面经。
4. “向量数据库与 MySQL 如何选择”等交叉题同时出现在 Agent 面经和通用基础文档。
5. 手撕、LeetCode 和 Vibe Coding 统一进入通用基础文档；若题目直接考查 Agent 工程能力，也在 Agent 面经保留。
6. 任何涉及个人经历、使用过的产品、线上数据或团队背景的问题，在信息不足时先与本人确认，不编造答案，也不使用回避式模板代替真实经历。
