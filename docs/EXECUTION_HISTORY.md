## 2. 主要架构决策

1. 简单请求直接进入领域 Agent，复杂请求才由 Planner 生成冻结计划并交给 Supervisor。
2. Supervisor 负责调度真实领域 Agent，但不能绕过安全、确认、Checkpoint 和事后评测。
3. Agent 只能通过 Tool Registry 读取数据库、Provider 和 RAG，不能直接持有数据库连接。
4. PostgreSQL 是任务和确认记录的权威存储；Redis 只做带 TTL 的缓存，故障时回源 PostgreSQL。
5. 不保存长期完整聊天，不建立个人健康向量记忆；医疗事实每次从权威业务数据重新读取。
6. 自动测试默认使用 deterministic provider；真实模型是可选运行模式，原始输出必须经过结构校验和安全检查。
7. 医疗知识采用 PostgreSQL、pgvector、FastEmbed、关键词检索和 RRF；个人数据不进入知识向量库。

## 4. RAG 优化记录

测试集由 120 篇合成文档、2307 个 Chunk、125 个 Base Case 和 500 条 Query 组成。最终保留方案依次解决三个问题：

1. **旧版本干扰召回**：把活动版本过滤提前到候选截断前，避免过期 Chunk 占用 Top-K。
2. **错误证据进入回答**：增加 Query 实体证据门和最小来源上下文，只把直接支持当前问题的来源交给模型。
3. **重复数据库读取**：在单次评测运行中复用只读知识快照，向量来源仍回 PostgreSQL 校验版本。

| 指标 | 优化前 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| Recall@5 | 70.96% | 85.19% | +14.23 个百分点 |
| 来源绑定回答准确率 | 23.44% | 63.75% | +40.31 个百分点 |
| 来源绑定幻觉率 | 51.25% | 7.50% | -43.75 个百分点 |
| 端到端 p95 | 3398.879 ms | 2187.268 ms | -35.65% |
| 总 token | 620,183 | 231,268 | -62.71% |
| 观测成本 | 0.675887 USD | 0.276581 USD | -59.08% |

最终运行 fallback rate 为 5.00%。这些结果来自 synthetic/test-only 数据、FastEmbed、PostgreSQL pgvector HNSW 和真实 OpenAI-compatible 模型，不是患者数据、临床准确率或生产 SLA。

## 5. 2026-08-12：5A-9 RAG 策略实验记录

本次仍使用冻结的 125 个基础 Case / 500 条 Query，不修改 Gold、不建立平行数据集、不增加人工审核门。目标是验证相似药品、规则片段和文档切分带来的召回与上下文污染问题。

1. **保留：BM25 + 向量双路召回。** 活动版本内执行 BM25 与 FastEmbed/pgvector HNSW，使用 RRF 融合。
2. **保留：候选过滤和轻量重排。** 先按显式实体过滤，候选 20 条按实体精确命中、双路命中、词项覆盖、RRF 与文档位置排序；只删除同一 Chunk 的重复来源。
3. **保留：文档主片段优先。** 命中被切分文档中的显式实体时，优先输出主片段；综合问题可追加紧邻补充片段。没有按 Gold ID 写死，但当前正样本 Gold 全部位于主片段或紧邻片段，因此只作为合成语料工程结论。
4. **不单独保留：忠实度提示词。** 单变量回答正确率为 65.94%（旧基线 63.75%），但确定性来源绑定幻觉率为 8.13%（旧基线 7.50%），未同时改善两项指标。

| 指标 | 旧冻结基线 | 最终组合 | 变化 |
| --- | ---: | ---: | ---: |
| Recall@3 / @5 / @10 | 67.50% / 85.19% / 95.38% | 100.00% / 100.00% / 100.00% | +32.50 / +14.81 / +4.62pp |
| Precision@3 / @5 / @10 | 25.00% / 21.38% / 12.46% | 43.59% / 26.15% / 13.08% | +18.59 / +4.77 / +0.62pp |
| MRR@10 | 0.5059 | 0.8125 | +0.3066 |
| 来源绑定回答正确率 | 63.75% | 74.69% | +10.94pp |
| 确定性来源绑定幻觉率 | 7.50% | 0.00% | -7.50pp |

最终真实模型运行完整 usage 覆盖率为 99.44%，fallback 为 0.56%。平均总 token 和平均成本分别增加 18.70% / 15.51%，端到端 P95 增加 24.98%；本地 CUDA 依赖未加载，运行环境和旧基线不一致，因此没有将延迟变化归因于检索策略。独立 Judge 复评返回账户计费不可用，Faithfulness、Response Relevancy 和 Context Recall 均保留为 N/A，不记为 0。无效的早期 BM25/rerank 组合曾使 Recall@3 降为 13.85%，调整后未加主片段优先的版本也仅为 60.38%，均未进入当前配置。

随后为解决“每题仅 1.31 个核心相关 Chunk、固定 Top-K Precision 被标签上限限制”的问题，未创建平行数据集，而是在同一数据集新增 `auto_expanded_relevant_chunk_ids` 与 `labels/auto_expanded_evidence.jsonl`。真实模型对 65 个正样本基础 Case 自动选择同文档的定义、条件、步骤、例外证据；每个角色最多一个、每题最多四条，65/65 成功且无 fallback，平均每题 3.95 条。直接复用已冻结 `retrieval_results.jsonl` 复算得到 Precision@3/@5/@10 为 60.51%/50.15%/31.81%。这代表 AI 自动标签覆盖扩展，不能表述为检索算法提升，也不覆盖原冻结 Gold 或用于临床/人工 Gold 结论。

随后对同一冻结 Top-10 候选做 Cross-Encoder 反证实验：使用 `BAAI/bge-reranker-base` 在 CPU 上重排 15 个基础 Case、60 条 Query，不新增候选、不改标签、也不调用回答模型。自动扩展证据 Precision@3/@5/@10 从 60.56%/53.33%/30.83% 变为 17.78%/23.67%/30.83%；原冻结 Gold Precision@3/@5 从 33.33%/20.00% 变为 0.00%/0.00%。通用模型将同主题补充片段排在当前生效的规则主片段前，违反本项目的业务排序约束，故该方案已拒绝，不接入主链路或简历。

真实 LLM 受限候选重排随后完成。`deepseek-v4-flash` 只允许输出同一 Top-10 的完整 ID 排列，提示词显式要求规则主定义、条件、步骤、例外、版本和精确实体优先；先以 1 个 Case/4 条 Query 冒烟成功，再在相同 15 个基础 Case、60 条 Query 对照。合法排列率 96.67%，真实 Provider 成功率 100%，1 条非法排列自动回退。自动扩展证据 Precision@3/@5/@10 由 60.56%/53.33%/30.83% 变为 55.00%/49.33%/30.83%，冻结 Gold 各档持平；每条额外平均 2,850 token、2.12 秒。没有质量净收益且成本较高，故方案已拒绝，不扩展全量、不进入主链路或简历。

真实 LLM 查询扩展随后完成。模型完全看不到语料，只能把原问句已经出现的规则编号、药品名、规格、动作和条件规范化；原问句始终保留，Provider 失败/超时/fallback 时强制只使用原问句，避免 fallback 文本污染检索。15 个基础 Case、60 条 Query 拆为 3 个独立分片，真实扩展成功率 100%、无 fallback。自动扩展证据 Precision@3/@5/@10 由 60.56%/53.33%/30.83% 变为 64.45%/54.33%/31.83%，但冻结 Gold Recall 和 Precision 各档均持平；每条额外约 220 token、1.88 秒。该收益仅反映自动多证据标签覆盖，未形成正式可比指标的净提升，故仅作为离线诊断留档，不进入默认链路或简历。

结构化过滤与父子 Chunk 检索随后做了实现核验。实验 profile 的规则是：子 Chunk 检索负责定位，显式实体过滤负责排除相似实体，回答上下文以同文档父主片段为先，综合问题再加入命中的子片段。60 条 Query retrieval-only 与真实 LLM 对照显示，现有 M5 的实体过滤、候选规则重排、主片段优先和最小证据门已经产生完全相同的模型输入证据（60/60）。因此核心检索指标持平；父子 profile 首跑的 98.33% 回答正确率来自首条 Provider fallback，单条重跑为 100%。没有新增主链路代码；后续若要真正升级，必须先引入 `parent_chunk_id` / `section_id` 元数据与独立人工多证据 Gold。
