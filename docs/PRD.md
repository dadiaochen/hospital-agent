# PRD: 互联网医院慢病续方与家庭用药管理 Agent 系统

## 1. 项目定位

本系统是面向互联网医院业务链路的家庭健康事务管理 Agent。它服务于用户长期健康管理，帮助用户整理家庭成员档案、历史处方、购药记录、家庭药箱、复诊续方材料、用药提醒和 Agent 执行记录。

系统不是 AI 医生，不提供诊断，不自动开方，不修改医生处方。

## 2. 目标用户

- 家庭健康事务主要管理者。
- 需要长期管理慢病用药的家庭。
- 需要定期复诊、补货、提醒和材料整理的互联网医院用户。

## 3. MVP 范围

MVP 只聚焦四个场景：

1. 父亲降压药慢病续方。
2. 母亲中医复诊材料整理。
3. 母亲用药提醒创建。
4. 高风险用药调整问题安全拦截。

## 4. 核心业务闭环

用户 / 家庭成员建档 -> 维护家庭药箱 -> 查询历史处方与购药记录 -> 估算药品剩余天数 -> 判断是否需要复诊续方 -> 生成补货或复诊续方方案 -> 查询药品库存与配送方案 -> 用户确认后创建购药方案 / 复诊申请 / 用药提醒 -> 记录 Agent 执行日志和工具调用日志。

## 5. 非目标

- 不做疾病诊断。
- 不自动开具处方。
- 不修改医生处方。
- 不绕过医生或用户确认。
- 不生成缺少来源依据的医疗建议。

## 6. 用户故事

### 6.1 父亲降压药续方

用户说：“我爸的降压药快吃完了，帮我看看能不能续方。”

系统应识别父亲和降压药场景，整理健康档案、历史处方、购药记录、剩余药量、处方有效性和药店库存，生成待确认续方或补货方案。

### 6.2 母亲中医复诊材料

用户说：“我妈上次开的中药快喝完了，帮我整理一下复诊材料。”

系统应整理历史问诊、处方、购药记录、近期变化和复诊申请草稿，等待用户确认后再提交。

### 6.3 母亲用药提醒

用户说：“帮我给妈妈设置每天早晚的用药提醒。”

系统应查询母亲当前药箱，生成提醒计划，等待用户确认后创建提醒任务。

### 6.4 高风险用药调整

用户说：“我爸这个药能不能加量？”

系统必须识别高风险医疗决策，不给出加量建议，提示咨询医生，并可辅助整理咨询问题。

## 7. 成功指标

- 用户可以用一句自然语言触发家庭健康事务流程。
- Agent 输出都能追溯到档案、处方、购药记录或知识库来源。
- 所有关键动作都有明确确认状态。
- 高风险医疗问题被安全拦截。
- Agent run 和 tool call 可查询、可回放。
