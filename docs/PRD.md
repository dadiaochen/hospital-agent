# 产品需求文档

## 1. 产品定位

这是一个面向互联网医院慢病续方、家庭药箱、用药提醒和安全确认的家庭健康事务管理 Agent。它负责信息整理、流程辅助、方案草稿和确认前准备，而不是替代医生。

## 2. 目标用户

- 负责管理家庭长期用药和复诊事务的用户。
- 有多个家庭成员、需要区分档案和用药信息的家庭。
- 需要整理处方、药箱、购药记录、提醒或复诊材料的慢病家庭。

## 3. MVP 闭环

```text
选择家庭成员
  -> 查询档案 / 处方 / 药箱 / 库存 / 安全规则
  -> 整理有来源的材料或草稿
  -> 识别风险并要求人工确认
  -> 只写入本地 draft
  -> 留下工具与 Agent trace 供回放和评估
```

## 4. 核心场景

| 场景 | 用户得到的结果 | 必要约束 |
| --- | --- | --- |
| 慢病续方材料 | 已有处方、药箱和购药记录的结构化整理 | 不开方、不改剂量、草稿需确认。 |
| 中医复诊材料 | 历史材料和待确认复诊草稿 | 不替代医生诊断。 |
| 用药提醒 | 根据药箱信息生成提醒草稿 | 创建前需要确认。 |
| 高风险问题 | 拒绝加量、减量、停药、换药等越界请求并引导人工处理 | SafetyAgent 在动作前拦截。 |

## 5. 非目标

- 疾病诊断、处方生成、处方修改或剂量调整。
- 自动向医院、药店、支付或提醒推送系统提交动作。
- 未经来源支持的病史、库存、处方或医疗规则生成。
- 生产级身份认证、权限运营和临床决策支持。

## 6. 产品成功条件

MVP 成功不是“回答像医生”，而是四个核心场景可以从 UI 和 API 演示入口完成可追踪的本地闭环：成员隔离、事实来源、确认门禁、安全拦截和 run 评估都能看见。详细交付顺序与验收标准见 [DEVELOPMENT_ROADMAP.md](DEVELOPMENT_ROADMAP.md)。
