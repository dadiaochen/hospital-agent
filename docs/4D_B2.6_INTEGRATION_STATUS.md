## 本次实现

### PostgreSQL materializer

`backend/app/agent/v2_integration.py` 中的 `PostgresV2Materializer` 为每个 case 建立独立临时 projection table，并在同一个 PostgreSQL session 中插入当前 case 的知识文档和 chunk。应用业务表只使用显式 identity map 指向的 demo rows；评测新增的 task/run/draft 和知识行在结束时回滚，不写入长期业务数据。

### RAG isolation

`ScopedPostgresRetriever` 仍调用项目现有 PostgreSQL hybrid retriever，再用当前 case 的 source allow-list 过滤结果。这样既能验证真实数据库检索和版本字段，又不会把 seed 数据或其他 case 的 source 混入当前 case。`no_source` case 的 allow-list 为空，不能硬答。

### Provider isolation

`ScopedProviderSandbox` 复用现有 deterministic Provider contract，只在当前 case 注入 timeout/no-source fault，并记录 attempt trace。它不会访问外部 Provider，也不会把网络结果当作正式指标。

### 业务图和契约适配

`UnifiedHealthGraphIntegrationExecutor` 使用明确的本地 identity/source map，将 benchmark ID 映射到 demo 用户、成员和 source，再执行真实业务图。工具能力名 `search_business_knowledge` 在 grader 中归一为评测能力 `search_safety_knowledge`；真实 RunTrace 仍保留实现中的工具名，避免隐藏审计事实。

提醒链路现在会读取当前处方、调用 reminder Provider prepare-draft，并记录 action-specific confirmation flag。`ReminderAgent` 获得的是只读处方权限，不获得执行权限。

## 运行方式

### Docker 全链路

先启动 Docker Desktop，然后在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\run_4d_b26_docker_regression.py --start --output-dir var\demo\4d-b26-docker
```

成功后会生成本地证据：

- `var/demo/4d-b26-docker/4d_b26_docker_regression.json`
- `var/demo/4d-b26-docker/4d_b26_docker_regression.md`
- `var/demo/4d-b26-docker/task12_backend_acceptance.json`

这些文件位于 `var/` 或 `output/`，不应提交到 GitHub。

### 第一条真实 v2 integration sample

身份映射必须是本机文件，不能提交。示例文件可以参考被 `.gitignore` 忽略的：
`var/demo/v2_identity_map.local.json`。

```powershell
$env:PYTHONPATH=(Resolve-Path 'backend').Path
$env:DATABASE_URL='postgresql+psycopg://hospital:hospital@localhost:5432/family_health'
$env:RAG_VECTOR_ENABLED='true'
.\.venv\Scripts\python.exe scripts\run_4d_b26_integration.py `
  --identity-map var\demo\v2_identity_map.local.json `
  --max-cases 1 `
  --split development `
  --allow-pending-review `
  --output-dir output\benchmarks\v2-integration
```

`--allow-pending-review` 只允许本地调试，不会把数据状态变成人工审核通过。正式运行前必须把 v2 WorldState/Query 审核并冻结 manifest，并为所有实际 demo 成员和知识 source 提供显式映射。

### A/B/C/D preview

```powershell
$env:PYTHONPATH=(Resolve-Path 'backend').Path
.\.venv\Scripts\python.exe scripts\run_4d_b26_ablation.py `
  --max-cases 16 `
  --split development `
  --output-dir output\benchmarks\4d-b26-ablation
```

A/B/C/D 定义如下：

| 条件 | 路由 | 执行 | 上下文 |
|---|---|---|---|
| A | 强制 Supervisor | 串行 | `all_history` |
| B | 自动路由 | 串行 | `all_history` |
| C | 自动路由 | 有界并行 | `all_history` |
| D | 自动路由 | 有界并行 | `dependency_only` |

默认脚本是 synthetic preview。真实 A/B/C/D 需要为每个 condition 创建带不同
`EvalRuntimeOptions` 的 `UnifiedHealthGraph` executor，仍复用同一 manifest、Provider、RAG、安全和确认策略。

如果本地 identity map 已覆盖要运行的 case，可以直接使用真实模式：

```powershell
$env:PYTHONPATH=(Resolve-Path 'backend').Path
$env:DATABASE_URL='postgresql+psycopg://hospital:hospital@localhost:5432/family_health'
$env:RAG_VECTOR_ENABLED='true'
python scripts/run_4d_b26_ablation.py `
  --mode integration `
  --identity-map var/demo/v2_identity_map.local.json `
  --max-cases 1 `
  --split development `
  --output-dir var/demo/4d-b26-ablation-integration
```

该命令会在同一评测规则下依次执行 A/B/C/D；缺少用户、成员或 source 映射时直接失败，不会跨成员猜测或回源。当前本地 map 只覆盖 1 个开发样例，因此真实模式目前用于验证执行边界，不能生成最终 300/1200 指标。
