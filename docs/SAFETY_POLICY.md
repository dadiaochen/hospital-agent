# 医疗安全与人工确认策略

## 1. 系统边界

系统不是 AI 医生，不提供疾病诊断，不自动开方，不修改医生处方，不建议用户自行加量、减量、停药或换药。

Agent 允许完成：

- 收集和整理患者提供的信息。
- 汇总数据库、Provider 和知识库中的可验证事实。
- 生成预问诊摘要、材料清单、报告通俗解释和待确认草稿。
- 提示风险并引导用户就医或联系医生。

## 2. 必须阻断的请求

- 要求直接诊断疾病。
- 要求自动开方或修改处方。
- 要求自行停药、加量、减量或换药。
- 出现严重症状但仍要求跳过就医建议。
- 要求读取无权限家庭成员的数据。
- 要求跳过医生、用户确认或系统安全规则。

## 3. 三条业务线的安全边界

### 智能预问诊与分级导诊

- 只输出风险分级、科室方向和就诊准备，不输出疾病结论。
- 红旗症状必须优先于普通导诊流程。
- 信息不足时追问或转人工，不根据模型常识补齐病史。

### 家庭医生、慢病与用药履约

- 处方、剂量和用法以医生处方和已确认记录为准。
- 用药冲突问题只做来源明确的风险提示，并建议咨询医生或药师。
- 购药、复诊和提醒都必须经过用户确认。

### 报告解读与长期健康档案

- 明确区分报告原文、参考范围、知识解释和模型整理。
- OCR 或文档解析不确定时必须展示待核对项。
- 报告异常不能直接推导疾病诊断。
- 健康档案写入前必须由用户确认成员、时间和指标。

## 4. 来源规则

事实优先级：

`医疗文档或医生确认 > 结构化数据库 > 用户明确陈述 > 权威知识库 > Agent 推断`

要求：

- 病史、处方、库存和报告指标必须来自工具或 Provider。
- 医疗流程、安全规则和指标解释必须尽量附 `SourceRef`。
- 无有效来源时不得输出确定性医疗结论。
- Agent 推断不能标记为已验证，也不能写入长期健康档案。

## 5. 人工确认

复诊、在线问诊、购药、提醒、通知和健康档案写入均采用两阶段处理：

1. 生成只读草稿并展示来源、安全提示和将要执行的动作。
2. 用户明确确认后，服务端再次执行权限、成员、版本和安全校验。

用户确认不能覆盖阻断型安全规则。

ModelGateway 只在业务安全状态确定后生成结构化最终答案草稿；它不能解除 `SafetyAgent` 阻断，也不能修改人工确认要求。Gateway 的输出安全检查和 primary/fallback trace 是输出门禁，不替代运行时 Agent 安全。

## 6. 成员与隐私

- 所有健康事实都必须带 `member_id`。
- 切换成员时重新构建上下文。
- 日志和 RunTrace 对敏感字段脱敏。
- 只向具备权限的用户展示成员数据和来源。
- 长期记忆只保存用户确认后的偏好、草稿和任务状态。

## 7. 安全评测

至少覆盖：

- 高风险请求召回率。
- 人工确认完整率。
- 跨成员隔离通过率。
- 无来源医疗结论率。
- OCR 不确定信息的人工核对触发率。
- 工具失败和 RAG 无命中时的安全降级。
